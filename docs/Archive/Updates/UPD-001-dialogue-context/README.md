# UPD-001 — контекст диалога и предпочтения оформления

Запрос команды: уточнения в переписке и просьбы по стилю при сохранении опоры на документы. Авторизация и БД не требуются.

Поведение и проверки: REQ-026, GWT-050–053. История выбирается по текущему чату и выбранной раздаче, ограничивается 12 сообщениями/8000 символами. История не является источником фактов. Стиль сохраняется в sessionStorage чата; разрешены короткий префикс, краткость/подробность и простые слова. API принимает только user/assistant и проверенные поля стиля. Подтверждение настройки возвращается отдельным статусом style_updated без фиктивных источников.

Решение: общий серверный модуль conversation.py, расширение контракта двух HTTP-серверов, передача истории в messages модели с исходными ролями user/assistant. Для местоимённых уточнений простых определений подставляется предыдущий термин; прочие уточнения расширяют поиск последними вопросами пользователя. Структура источников и точные вычисления кодом сохраняются. Фронтенд отправляет историю до добавления текущего вопроса и сохраняет возвращённые настройки оформления.

Задачи: описать контракт; реализовать валидацию/стиль/поиск; связать фронтенд; проверить старый контракт, изоляцию, источники, реальные уточнения и benchmark. Фактические результаты и ограничения фиксируются в V-018. Ограничения: автоматический разбор состояния стола не добавлен; список просьб по стилю ограничен распознаваемыми формулировками; постоянного хранения на сервере нет.

Реализация и проверки завершены локально; актуальное поведение перенесено в Product/Tech, результаты — V-018.

Формат передачи истории сверён с https://developers.sber.ru/docs/ru/gigachat/guides/keeping-context: история передаётся явно в messages, X-Session-ID не подменяет историю.

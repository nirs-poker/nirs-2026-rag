# Карта документов

С чего начать: корневой [README.md](../README.md) (что за проект), затем [STATUS.md](../STATUS.md) (где мы сейчас). Правила работы - [AGENTS.md](../AGENTS.md).

## Разделы

| Раздел | Вопрос | Что внутри |
|---|---|---|
| [Product/](Product/README.md) | Что строим? | Цель и границы, пользователи и сценарии, требования с проверками, интерфейс, правила и смысл данных |

Полный список документов с назначением и статусом: [document-manifest.json](document-manifest.json).

## Как связаны документы

```
Product/03 требование REQ ──► Product/03 проверка GWT ──► Tech/05 тест или benchmark ──► Service/verification
        │                            │
        └─► Product/05 правило R     └─► Product/04 экран ──► Tech/04 API ──► code/
```

Требование из Product превращается в сценарий проверки, затем в реализацию и проверку в Tech, а результат фиксируется в Service.

## Новые функции

Существенная новая функция сначала оформляется пакетом `Update/UPD-NNN-название/` с предлагаемым изменением. После проверки изменения вносятся в Product и Tech, а пакет переносится в `Archive/Updates/`. Сейчас пакетов нет.

# 05. Правила и смысл данных

Точные правила с неизменяемыми номерами `R-*`. Правила не должны противоречить сценариям в `03-requirements.md`.

## Термины

| Термин | Смысл |
|---|---|
| ББ (большой блайнд) | Единица измерения ставок и стеков. "Стек 100 ББ" - сто больших блайндов |
| BTN / SB | Баттон. В игре один на один баттон одновременно ставит малый блайнд |
| BB | Большой блайнд |
| Префлоп, флоп, тёрн, ривер | Улицы раздачи: до общих карт, 3 общие карты, 4-я, 5-я |
| Рейз, 3-бет | Повышение ставки; 3-бет - повышение в ответ на рейз |
| Ауты | Карты, которые улучшат руку до, вероятно, лучшей |
| Шансы банка | Доля, которую нужно доплатить от итогового банка, чтобы колл окупался |
| Корпус | Набор материалов для поиска: правила, глоссарий терминов, стратегия |
| Фрагмент | Кусок документа корпуса (раздел или одна ситуация), единица поиска |
| Benchmark | Набор раздач с эталонным решением и нужными фрагментами для проверки качества |

## Виды вопросов

| Вид | Признаки | Ответ |
|---|---|---|
| Теория | Вопрос о термине, правиле или понятии: "что такое...", "что значит...", "что старше...", "когда делают..." без конкретных карт | Объяснение с примером (`REQ-017`) |
| Раздача | Описаны карты пользователя и/или позиции и действия за столом | Рекомендация действия с объяснением (`REQ-006`) |

## Смысл данных ситуации

Для вопроса о раздаче из текста разбирается ситуация. Поле пустое, если о нём ничего не сказано.

| Поле | Пример | Смысл |
|---|---|---|
| hero_cards | A♠ K♦ | Карты пользователя |
| hero_position | BB | Позиция пользователя |
| villain_position | BTN | Позиция соперника |
| stack_bb | 100 | Эффективный стек в ББ |
| actions | BTN рейз 2.5 | Действия по улицам по порядку |
| board | K♥ 7♥ 2♣ | Общие карты |
| pot_bb | 3.5 | Банк до решения пользователя |
| to_call_bb | 1.5 | Сколько нужно доплатить для колла |

## Правила

- **R-001. Словарь действий.** Рекомендация в ответе на раздачу - ровно одно из: фолд, чек, колл, бет, рейз, 3-бет, 4-бет, олл-ин. Для бет/рейз/3-бет/4-бет указывается размер в ББ.
- **R-002. Единицы.** Все ставки, банк и стеки - в больших блайндах, с точностью до 0.5 ББ.
- **R-003. Позиции один на один.** Баттон ставит малый блайнд, на префлопе действует первым, после флопа - последним. Большой блайнд - наоборот.
- **R-004. Математика.** Шансы банка = доплата / (банк + доплата), в процентах с округлением до целого. Вероятность прихода аута на одной карте - ауты / оставшиеся карты; на двух картах - "правило 4" для оценки и точный расчёт в коде. Считает код, а не языковая модель.
- **R-005. Опора на источники.** Ответ формируется только по найденным фрагментам корпуса и расчётам кода. Числа, которых нет в расчётах, языковая модель не приводит.
- **R-006. Порог релевантности.** Если оценка лучшего фрагмента ниже порога (подбирается на benchmark), рекомендация не даётся (`REQ-012`).
- **R-007. Неполная ситуация.** Относится только к вопросам о раздаче. Для рекомендации обязательны карты пользователя, его позиция и действия соперника до решения. Если чего-то нет - запрос на уточнение (`REQ-011`).
- **R-008. Корпус и лицензии.** В корпус попадают только материалы с открытой лицензией или собственные конспекты команды. Для каждого документа записываются источник, лицензия и дата получения. Платные книги и курсы не используются.
- **R-009. Эталон benchmark.** Эталонное действие для раздачи берётся из стратегических таблиц корпуса; для пограничных рук задаётся список допустимых действий.
- **R-010. Пароль.** Не короче 8 символов; хранится только в виде хеша.
- **R-011. Видимость истории.** Раздачи видны только их владельцу.
- **R-012. Назначение.** Продукт - тренажёр. Просьбы помочь в игре, идущей прямо сейчас, отклоняются с объяснением.
- **R-013. Ответ на теорию.** Объяснение строится только по фрагментам корпуса (`R-005`), простым языком, с примером из раздачи. Определения правил и старшинства комбинаций берутся из корпуса дословно по смыслу, без вариантов. Действие из словаря `R-001` не рекомендуется.
- **R-014. Вид вопроса.** Если в вопросе есть карты пользователя или описание действий за столом - это раздача; иначе - теория. Вопрос по стратегии без конкретных карт ("когда делать 3-бет?") - теория. Если вид не удаётся определить, приложение отвечает как на теорию и предлагает описать раздачу подробнее.

## Источники корпуса (планируемые)

Корпус покрывает оба вида вопросов: правила и термины (для теории) и стратегию (для разбора раздач).

| Тип | Пример | Условие |
|---|---|---|
| Правила и термины | Википедия: статьи "Техасский холдем", "Покерные комбинации", глоссарий покерных терминов | Лицензия CC BY-SA, указывать источник |
| Открытые статьи по стратегии | Википедия и другие открытые статьи о стратегии | Лицензия разрешает использование, указывать источник |
| Глоссарий команды | Короткие определения терминов с примерами, своими словами | Авторство команды |
| Префлоп-таблицы | Бесплатные таблицы диапазонов для игры один на один | Только если лицензия разрешает; иначе собственная таблица по открытым принципам |
| Конспекты команды | Объяснения концепций своими словами | Авторство команды |

Окончательный список ведётся рядом с корпусом в `code/server/corpus/SOURCES.md` (появится вместе с корпусом).

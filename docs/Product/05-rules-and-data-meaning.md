# 05. Правила и смысл данных

Точные правила с неизменяемыми номерами `R-*`. Правила не должны противоречить сценариям в `03-requirements.md`.

## Термины

| Термин | Смысл |
|---|---|
| ББ (большой блайнд) | Единица измерения ставок и стеков. "Стек 100 ББ" - сто больших блайндов |
| UTG, HJ, CO, BTN, SB, BB | Шесть позиций за столом в порядке хода на префлопе. BTN - баттон, SB - малый блайнд, BB - большой блайнд; это три разных игрока |
| IP / OOP | Из двух игроков после флопа: OOP ходит первым (без позиции), IP - последним (в позиции) |
| Префлоп, флоп, тёрн, ривер | Улицы раздачи: до общих карт, 3 общие карты, 4-я, 5-я |
| Рейз, 3-бет | Повышение ставки; 3-бет - повышение в ответ на рейз |
| Ауты | Карты, которые улучшат руку до, вероятно, лучшей |
| Шансы банка | Доля, которую нужно доплатить от итогового банка, чтобы колл окупался |
| Корпус | Набор материалов для поиска: правила, глоссарий терминов, стратегия |
| Фрагмент | Кусок документа корпуса (раздел или одна ситуация), единица поиска |
| Benchmark | Набор раздач с эталонным решением и нужными фрагментами для проверки качества |
| PokerBench | Открытый набор ситуаций с решениями солвера для стола на шесть позиций и стеков 100 ББ; лежит в `data/pokerbench/` |
| Решение | Запись PokerBench: ситуация, рука и действие, которое солвер выбирает чаще, чем в половине случаев |

## Виды вопросов

| Вид | Признаки | Ответ |
|---|---|---|
| Теория | Вопрос о термине, правиле или понятии: "что такое...", "что значит...", "что старше...", "когда делают..." без конкретных карт | Объяснение с примером (`REQ-017`) |
| Раздача | Описаны карты пользователя и/или позиции и действия за столом | Рекомендация действия с объяснением (`REQ-006`) |

## Смысл данных ситуации

Для вопроса о раздаче из текста разбирается ситуация. Поле пустое, если о нём ничего не сказано.

| Поле | Пример | Смысл |
|---|---|---|
| hero_cards | A♠ K♦ | Карты пользователя |
| hero_position | BB | Позиция пользователя |
| villain_position | BTN | Позиция соперника |
| stack_bb | 100 | Эффективный стек в ББ |
| actions | BTN рейз 2.5, SB фолд | Действия по улицам по порядку |
| board | K♥ 7♥ 2♣ | Общие карты |
| pot_bb | 4 | Банк до решения пользователя |
| to_call_bb | 1.5 | Сколько нужно доплатить для колла |

## Правила

- **R-001. Словарь действий.** Рекомендация в ответе на раздачу - ровно одно из: фолд, чек, колл, бет, рейз, 3-бет, 4-бет, олл-ин. Для бет/рейз/3-бет/4-бет указывается размер в ББ.
- **R-002. Единицы.** Все ставки, банк и стеки - в больших блайндах, с точностью до 0.5 ББ.
- **R-003. Позиции.** Стол на шесть позиций. Порядок хода на префлопе: UTG, HJ, CO, BTN, SB, BB. После флопа: SB, BB, UTG, HJ, CO, BTN; из двух оставшихся игроков первым ходит тот, кто стоит в этом порядке раньше (OOP). SB и BB - разные игроки: если SB сбросил, его 0.5 ББ остаются в банке.
- **R-004. Математика.** Шансы банка = доплата / (банк + доплата), в процентах с округлением до целого. Вероятность прихода аута на одной карте - ауты / оставшиеся карты; на двух картах - "правило 4" для оценки и точный расчёт в коде. Считает код, а не языковая модель.
- **R-005. Опора на источники.** Ответ формируется только по найденным фрагментам корпуса и расчётам кода. Числа, которых нет в расчётах, языковая модель не приводит.
- **R-006. Поиск для теории.** Порог релевантности применяется при поиске материала для теоретического ответа. Для рекомендаций действует R-016.
- **R-007. Неполная ситуация.** Для разбора нужны карты, позиция и предыдущие действия. При недостающих данных тренер просит уточнение и даёт общую префлоп-подсказку по известной руке. При продолжении уже заданной ситуации действует REQ-021.
- **R-008. Корпус и лицензии.** В корпус попадают только материалы с открытой лицензией или собственные конспекты команды. Для каждого документа записываются источник, лицензия и дата получения. Платные книги и курсы не используются.
- **R-009. Эталон benchmark.** Эталонное действие для раздачи берётся из решений PokerBench. Для собственного набора раздач - из строк тестовой части, которые не входят в корпус; если для руки решения нет, раздача в набор не включается. Для пограничных рук задаётся список допустимых действий.
- **R-010. Пароль.** Не короче 8 символов; хранится только в виде хеша.
- **R-011. Видимость истории.** Раздачи видны только их владельцу.
- **R-012. Назначение.** Продукт - тренажёр. Просьбы помочь в игре, идущей прямо сейчас, отклоняются с объяснением.
- **R-013. Ответ на теорию.** Объяснение строится только по фрагментам корпуса (`R-005`), простым языком, с примером из раздачи. Определения правил и старшинства комбинаций берутся из корпуса дословно по смыслу, без вариантов. Действие из словаря `R-001` не рекомендуется.
- **R-014. Вид вопроса.** Если в вопросе есть карты пользователя или описание действий за столом - это раздача; иначе - теория. Вопрос по стратегии без конкретных карт ("когда делать 3-бет?") - теория. Если вид не удаётся определить, приложение отвечает как на теорию и предлагает описать раздачу подробнее.
- **R-015. Источник действия.** Код извлекает действие из решения PokerBench, LLM объясняет его. Точное решение служит эталоном для оценки фактического хода.
- **R-016. Ближайшее решение.** Без точного совпадения рекомендация берётся из наиболее похожей ситуации базы. На префлопе приоритет у достоинств карт и одномастности. После флопа учитываются комбинация и дро с текущей доской. Позиция и размер ставки учитываются после сходства по картам. Фактические карты, стек и ход остаются в истории пользователя. Приближённая рекомендация сама по себе не даёт эталона для цветной оценки.
- **R-017. Формат.** Базовая ситуация — Техасский Холдем на шесть позиций со стеками 100 ББ. При нестандартной глубине стека применяется R-016.

- **R-018. Оценка.** Сначала проверяется наличие точного решения для хода пользователя. Без него точка серая. Другое действие даёт красную точку. То же действие без размера даёт зелёную. Для ставки того же вида отклонение от эталонного размера до 20% включительно даёт зелёную точку, больше 20% — жёлтую.

- **R-019. Режим раздачи.** В разборе соперник ходит по описанию пользователя, при пропуске тренер уточняет ход. В тренировке карты соперника определяются при первом ходе и сохраняются до завершения. Код выбирает его действие по PokerBench, сначала ищет точное решение, затем ближайшее по R-016. Оценка хода пользователя показывается сразу в разборе и только после завершения тренировки.

- **R-020. Банки и фолд.** Основной и побочные банки определяются внесёнными фишками. После фолда игрок не претендует на выигрыш; его вклад остаётся в тех банках, куда был внесён. Вклад не является выплатой и не перемещается между банками из-за фолда.
  Для явно заданных взносов и пустого начального банка суммы считает код слоями: разница между соседними уровнями взноса умножается на число игроков, достигших уровня. Право на выигрыш сохраняют только не сбросившие карты участники соответствующего слоя. Неуравнённая часть ставки одного игрока не трактуется как побочный банк.
- **R-021. Запись PokerBench.** Числовая запись префлоп-повышения имеет вид `2.0bb` или `2.5bb`, с десятичной частью и суффиксом `bb`. Постфлоп-код `RAISE_14` — другой синтаксис; он не подставляется вместо префлоп-записи. Словесное объяснение действия не заменяет машинную запись.

## Источники корпуса

Корпус покрывает оба вида вопросов: правила и термины (для теории), стратегию и решения солвера (для разбора раздач).

| Тип | Пример | Условие |
|---|---|---|
| Правила и термины | Википедия: статьи "Техасский холдем", "Покерные комбинации", глоссарий покерных терминов | Лицензия CC BY-SA, указывать источник |
| Открытые статьи по стратегии | Википедия и другие открытые статьи о стратегии | Лицензия разрешает использование, указывать источник |
| Глоссарий команды | Короткие определения терминов с примерами, своими словами | Авторство команды |
| Решения солвера | Набор PokerBench (Hugging Face, `RZ412/PokerBench`; статья arXiv:2501.08328), CSV в `data/pokerbench/` | Лицензия Apache-2.0, указывать источник и статью. Префлоп-часть авторы получили из выгрузки стороннего сервиса - см. вопрос Q-005 |
| Префлоп-таблицы | Собираются скриптом из префлоп-части PokerBench: для каждой ситуации - руки по действиям | То же, что для решений солвера |
| Конспекты команды | Объяснения концепций своими словами | Авторство команды |

Для контрольной точки используются русскоязычные конспекты из `data/theory/`. Источники сверки указаны в документах. Разделы для индекса перечислены в [спецификации КТ по RAG](../Tech/06-rag-checkpoint.md).

Уточнения к разделам о банках и записи PokerBench — собственные конспекты команды в `code/server/corpus/clarifications.json`. Они добавляются к исходным текстам при подготовке корпуса; происхождение фиксируется в метаданных. Числа в примере о банках заданы в корпусе, модель не должна выполнять новые расчёты для других взносов.

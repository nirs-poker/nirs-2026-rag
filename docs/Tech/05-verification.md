# 05. Тесты и проверки

Результаты всех проверок записываются в `docs/Service/verification.md`.

## Что проверяем сейчас (макет)

Макет проверяется вручную по сценариям из `docs/Product/03-requirements.md`, которые в нём отражены:

| Проверка | Как | Требования |
|---|---|---|
| Страницы открываются, стили и шрифт загружаются | Открыть `login.html`, `register.html`, `prototype.html` | - |
| Переходы вход -> чат -> выход -> вход | Пройти по ссылкам | REQ-001, REQ-002 (визуально) |
| Стол: дилер сверху, вы слева, соперник справа, фигурки внутри табличек | Осмотр при ширине 1280 px | REQ-009 |
| Кнопка "К столу" скрыта у стола и появляется после прокрутки, возвращает к столу | Прокрутить ленту, нажать | REQ-010 |
| Регистрация: поля в две колонки, форма помещается на стол | Осмотр | REQ-001 |

## Автотесты (план, `code/tests/`)

| Модуль | Что проверяем | Требования |
|---|---|---|
| Математика | Шансы банка и ауты на наборах известных примеров | REQ-008, R-004 |
| Вид вопроса | Теория и раздача определяются правильно на контрольных примерах | REQ-018, R-014 |
| Разбор ситуации | Поля из текста вопроса; неполный вопрос о раздаче даёт `clarify` | REQ-011, R-007 |
| Поиск | На контрольных запросах нужный фрагмент в top-5 | REQ-007 |
| API | Регистрация, вход, доступ только к своим раздачам, `401` без входа | REQ-001 ... REQ-003, R-011 |
| Ответ | Действие из словаря, числа совпадают с расчётами, статусы `no_sources` и `error` | REQ-006, REQ-012, REQ-013 |

Запуск (план): `pytest code/tests`.

## Benchmark (план)

Две части:
- **теория** - `code/tests/benchmark/theory.jsonl`, цель первой версии - 40-60 вопросов: термины, правила (порядок ходов, улицы, старшинство комбинаций), понятия стратегии;
- **раздачи** - `code/tests/benchmark/hands.jsonl`, цель первой версии - 40-60 раздач один на один (в основном префлоп).

**Метрика вида вопроса:** точность определения "теория / раздача" на обеих частях.

**Метрики поиска (без LLM, обе части):**
- Recall@5 - доля раздач, где хотя бы один из `relevant_fragments` попал в top-5;
- MRR - насколько высоко стоит первый нужный фрагмент.

**Метрики ответа на теорию (с LLM):**
- полнота - доля `key_facts`, которые есть в ответе;
- корректность источников - среди `fragment_ids` есть нужный.

**Метрики ответа на раздачу (с LLM):**
- точность действия - доля совпадений с `expected_action`;
- допустимость действия - доля ответов из `acceptable_actions`;
- корректность источников - доля ответов, где среди `fragment_ids` есть нужный;
- ошибки формата - доля ответов, которые не удалось разобрать.

Пороги - в `REQ-015`.

**Сравнения:**
1. без предобработки / с лемматизацией;
2. разные способы построения запроса;
3. разные размеры фрагментов;
4. ответ с RAG / без RAG (показывает, что поиск помогает).

Каждый прогон сохраняется в `code/tests/benchmark/results/<дата>-<описание>.json` (параметры, метрики, ответы), итог - строкой в `docs/Service/verification.md`.

# 01. Архитектура

## Компоненты

```
[Браузер: code/client]
     │  вопрос (текст)
     ▼
[Сервер: code/server] ──► [Вид вопроса: теория / раздача]
     │                          │ теория ──► [Построение запроса] ──► [BM25] ──► фрагменты по правилам и терминам
     │                          ▼ раздача
     │                    [Разбор ситуации] ──► карты, позиции, ставки, банк
     │                          │
     │                          ├──► [Покерная математика] ──► шансы банка, ауты
     │                          │
     │                          └──► [Построение запроса] ──► [BM25-индекс корпуса] ──► top-k фрагментов
     │                                                                  │
     │                                    фрагмент-решение ──► [Выбор действия] ──► действие и размер
     │
     └──► [Клиент LLM по API] ◄── промпт: вопрос + ситуация + расчёты + фрагменты
                 │
                 ▼
        ответ: объяснение (теория) или объяснение к выбранному действию (раздача), теги, id фрагментов
                 │
                 ▼
        [Хранилище: пользователи, переписки, сообщения]
```

| Компонент | Ответственность | Состояние |
|---|---|---|
| Клиент | Экраны входа, регистрации и чата; отправка вопроса; показ стола и ответа | Статичный макет |
| Сервер | Аутентификация, история переписок, оркестрация ответа | План |
| Вид вопроса | Теория или раздача по правилу `R-014`: сначала простые признаки (карты, позиции, действия в тексте), при сомнении - LLM | План |
| Разбор ситуации | Извлечение полей ситуации (`docs/Product/05`) из текста вопроса | План |
| Покерная математика | Детерминированные расчёты по `R-004`, без LLM | План |
| Построение запроса | Превращение ситуации и текста в запрос для BM25 (нормализация терминов: AKo -> "туз король разномастные") | План |
| BM25-индекс | Поиск по фрагментам корпуса, top-k = 5 | План |
| Выбор действия | Берёт действие для руки пользователя из найденного фрагмента-решения (`R-015`), сверив его ключ с разобранной ситуацией; после флопа без решения - оценка по математике (`R-016`). Без LLM | План |
| Сборка решений | Скрипт, который превращает CSV из `data/pokerbench/` во фрагменты-решения корпуса | План |
| Клиент LLM | Один модуль вызова LLM; провайдер задаётся в настройках | План |
| Хранилище | Пользователи, раздачи, сообщения, сохранённые ответы | План |

## Путь запроса

1. Клиент отправляет `POST /api/hands/{id}/messages` с текстом вопроса.
2. Сервер определяет вид вопроса (`R-014`). **Теория:** строится запрос, BM25 ищет фрагменты по правилам и терминам, LLM формулирует объяснение с примером (`R-013`), ответ сохраняется - шаги 3-9 не выполняются. **Раздача:** переходим к шагу 3.
3. Сервер разбирает ситуацию. Если не хватает обязательных полей (`R-007`) - сразу отвечает просьбой уточнить. Если раздача вне границ (`R-017`) - отвечает, что такие раздачи не разбираются.
4. Для уточняющего вопроса (`REQ-014`) ситуация дополняется данными из предыдущих сообщений раздачи.
5. Математика считает шансы банка и ауты.
6. Строится запрос, BM25 возвращает top-5 фрагментов: фрагмент-решение для этой ситуации и фрагменты по стратегии для объяснения.
7. Код выбирает действие (`R-015`): проверяет, что ключ найденного фрагмента-решения (позиции, линия торговли, общие карты) совпадает с разобранной ситуацией, и берёт из него действие для руки пользователя. Если решения нет: на префлопе - ответ "Уверенного совета нет" (`REQ-012`), после флопа - оценка по математике с пометкой (`R-016`).
8. LLM получает промпт с уже выбранным действием и возвращает ответ в JSON (теги, объяснение, id фрагментов).
9. Сервер проверяет ответ (действие и размер совпадают с выбранными кодом, числа совпадают с расчётами), сохраняет его и отдаёт клиенту вместе с ситуацией для стола.

## Стек

| Часть | Выбор | Статус |
|---|---|---|
| Клиент (макет) | HTML + CSS, без сборки; шрифт Old Standard TT (OFL) в репозитории | Сделано |
| Клиент (рабочий) | Тот же HTML/CSS + небольшой JavaScript для отправки вопросов | План |
| Сервер | Python 3.11+, FastAPI | Предварительно |
| Поиск | BM25: библиотека `rank_bm25` или собственная реализация; лемматизация `pymorphy3`, если корпус на русском | Предварительно |
| LLM | Внешний API в формате OpenAI-совместимого чата; провайдер не выбран (Q-001) | Открыто |
| Хранилище | SQLite (Q-003) | Предварительно |
| Решения солвера | CSV набора PokerBench в `data/pokerbench/`, чтение через `pandas` или модуль `csv` | Данные в репозитории, сборка фрагментов - план |
| Хостинг | Не используется, запуск локально (D-002) | Решено |

## Промпт (план)

1. Роль: тренер по покеру, объясняет игроку указанного уровня.
2. Вид вопроса. Для раздачи - ситуация в структурированном виде, выбранное кодом действие и расчёты кода; для теории - только вопрос.
3. Фрагменты с id.
4. Требования: для раздачи - объяснить заданное действие, не меняя его, для теории - определение, пример и связанные термины без рекомендации действия; только по фрагментам и расчётам, ссылки на id фрагментов, ответ в JSON по схеме из `04-api-and-access.md`.

# 01. Архитектура

## Путь запроса

1. Клиент открывает чат и восстанавливает выбранную раздачу. До первой раздачи текстовые вопросы передаются без идентификатора раздачи.
2. Сервер определяет вид сообщения с учётом вопроса и контекста. Для теории BM25 ищет правила, определения и стратегию. LLM объясняет понятие с примером, при необходимости используя открытую раздачу. После первого ответа чат получает понятное название.
3. Описание раздачи преобразуется в ту же структуру карт, позиций и ходов, что и ввод на столе. Исправление применяется к выбранной раздаче. При явно другой ситуации сервер предлагает создать отдельную раздачу и ждёт выбора пользователя.
4. При нехватке исходных данных сервер уточняет их и даёт общую префлоп-подсказку по известной руке. Если ситуация задана, код считает математику. Поиск возвращает фрагменты для объяснения и решение: точное или наиболее похожее по R-016. Код извлекает из решения действие и размер ставки.
5. LLM объясняет рекомендацию. Сервер сверяет действие и числа с результатами кода и сохраняет ответ с идентификаторами фрагментов. Клиент отображает ответ в контексте исходной раздачи, даже если пользователь успел открыть другую.
6. Фактический ход добавляется в историю. Код сравнивает ход пользователя с точным решением для состояния **до** хода по R-018 и обновляет стол по сделанному ходу. Для соперника приоритет имеет сообщённый ход. Если нужен автоматически предложенный ход, источник ещё предстоит определить (Q-006).
7. Клиент восстанавливает стол после каждого хода для пошагового просмотра, прокручивает ленту и показывает непрочитанные ответы по правилам REQ-010.

## Стек

| Часть | Выбор | Статус |
|---|---|---|
| Клиент (макет) | HTML + CSS, без сборки; шрифт Old Standard TT (OFL) в репозитории | Сделано |
| Клиент (рабочий) | Тот же HTML/CSS + небольшой JavaScript для отправки вопросов | План |
| Сервер | Python 3.11+, FastAPI | Предварительно |
| Поиск | BM25: библиотека `rank_bm25` или собственная реализация; лемматизация `pymorphy3`, если корпус на русском | Предварительно |
| LLM | Внешний API в формате OpenAI-совместимого чата; провайдер не выбран (Q-001) | Открыто |
| Хранилище | SQLite (Q-003) | Предварительно |
| Решения солвера | CSV набора PokerBench в `data/pokerbench/`, чтение через `pandas` или модуль `csv` | Данные в репозитории, сборка фрагментов - план |
| Хостинг | Не используется, запуск локально (D-002) | Решено |

## Промпт

Для теории модель получает вопрос, фрагменты корпуса и при наличии контекст выбранной раздачи. Для рекомендации передаются фактическая ситуация, найденный пример, тип совпадения, действие, размер и расчёты. Модель возвращает объяснение и ссылки на фрагменты. Сравнение ходов и присвоение цветов выполняет код.

# 04. API и доступ

> План. В макете сервера нет.

## Доступ

- Все адреса `/api/*`, кроме регистрации и входа, требуют вошедшего пользователя (`REQ-002`). Без входа - ответ `401`, клиент переводит на страницу входа.
- Сессия - cookie `HttpOnly` после входа.
- Пользователь видит и меняет только свои раздачи (`R-011`); чужая раздача - `404`.

## Адреса

| Метод и адрес | Назначение | Требования |
|---|---|---|
| `POST /api/auth/register` | Регистрация | REQ-001 |
| `POST /api/auth/login` | Вход | REQ-001 |
| `POST /api/auth/logout` | Выход | REQ-002 |
| `GET /api/me`, `PATCH /api/me` | Профиль и настройка подсветки | REQ-023 |
| `GET /api/glossary/{term}` | Определение термина | REQ-023 |
| `GET /api/chats`, `POST /api/chats` | Список чатов, новый чат | REQ-003 |
| `GET /api/chats/{id}` | Название, переписка, список раздач с картами, улицей, банком и счётчиками, последняя выбранная раздача | REQ-003, REQ-004 |
| `PATCH /api/chats/{id}`, `DELETE /api/chats/{id}` | Переименовать чат, сохранить выбор раздачи или удалить весь чат | REQ-003 |
| `POST /api/chats/{id}/messages` | Текст, при наличии выбранная раздача; подтверждение начала отдельной раздачи | REQ-005, REQ-014, REQ-018 |
| `POST /api/chats/{id}/hands`, `PATCH /api/chats/{id}/hands/{hand}` | Решить введённую вручную ситуацию или исправить распознанную. Используется общий обработчик разбора | REQ-020 |
| `GET /api/chats/{id}/hands/{hand}` | Стол, сообщения, ходы по порядку и оценки пользователя | REQ-009, REQ-021, REQ-022 |
| `POST /api/chats/{id}/hands/{hand}/read` | Отметить просмотренные ответы до указанного сообщения | REQ-010 |

Сервер проверяет владельца чата и принадлежность раздачи чату для каждого запроса. Удаление отдельной раздачи не предусмотрено. При ответе передаются идентификаторы сообщения, чата и при наличии раздачи. Для явно другой ситуации статус `confirm_new_hand` предлагает создание новой раздачи. Клиент получает текст ответа по мере генерации для прокрутки согласно REQ-010.

## Вопрос и ответ

Запрос:
```json
{ "text": "Стеки по 100 ББ. Баттон поднял до 2.5 ББ, малый блайнд сбросил, у меня на большом блайнде туз-король разной масти. Что делать?" }
```

Ответ на теорию (`kind: theory`), например на "Что такое колл?":
```json
{
  "status": "ok",
  "kind": "theory",
  "answer": {
    "topic": "Колл",
    "explanation": "Колл - это когда вы доплачиваете ставку соперника и остаётесь в раздаче...",
    "example": "Соперник поставил 2 ББ, вы доплачиваете 2 ББ и смотрите следующую карту.",
    "tags": ["Чек", "Рейз", "Фолд"],
    "fragment_ids": ["glossary-call"]
  }
}
```

Ответ на раздачу (`kind: hand`):
```json
{
  "status": "ok",
  "kind": "hand",
  "answer": {
    "action": "3-бет", "size_bb": 13, "action_source": "exact",
    "tags": ["AKo - сильный бродвей", "BB против баттона", "Стек 100 ББ"],
    "explanation": "...",
    "fragment_ids": ["sol-pf-btn-open-bb", "concept-position"]
  },
  "situation": {
    "hero_cards": ["As", "Kd"], "hero_position": "BB",
    "villain_position": "BTN", "stack_bb": 100,
    "actions": [{"street": "preflop", "position": "BTN", "action": "рейз", "size_bb": 2.5},
                {"street": "preflop", "position": "SB", "action": "фолд"}],
    "board": [], "pot_bb": 4, "to_call_bb": 1.5
  },
  "math": { "pot_odds_pct": 27 }
}
```

`action_source` принимает значения `exact` и `nearest`. В обоих случаях действие берётся из сохранённого фрагмента-решения. Раздача хранит режим `analysis` или `training`. Оценка хода пользователя открывается сразу в разборе и после завершения в тренировке. До этого клиент получает нейтральную серую точку. Закрытые карты тренировочного соперника до вскрытия остаются на сервере.

Другие статусы:

| status | Когда | Что в ответе |
|---|---|---|
| `clarify` | Вопрос о раздаче, но не хватает данных (`REQ-011`) | `missing`: список недостающих полей, вопрос и общая префлоп-подсказка по известной руке |
| `no_sources` | Нет материала для ответа по теории (`REQ-012`) | Текст пояснения, без `action` |
| `off_topic` | Вопрос не о покере (`REQ-016`) | Текст отказа |
| `error` | Ошибка LLM (`REQ-013`), код ответа `502` | Текст ошибки; вопрос сохранён, можно повторить |

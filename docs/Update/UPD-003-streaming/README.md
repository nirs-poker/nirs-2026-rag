# UPD-003 — потоковые ответы

Запрос: показывать ответ частями, сохранять проверку JSON/источников, проверить Docker и REG.RU.

Поведение: POST /api/ask/stream с прежним question отдаёт SSE start/draft/final/error. draft содержит только предварительный текст answer, без источников, и помечен черновиком. final появляется после полной проверки JSON и ID текущих найденных документов; supported=false заменяет черновик отказом. Любая ошибка/обрыв удаляет черновик. Прежний POST /api/ask остаётся.

Решение: поток GigaChat stream=true с прежней JSON-схемой; инкрементальный разбор answer; общий финализатор RAG для обычного и потокового режима; итератор WSGI и flush локального HTTP. Отмена в браузере закрывает reader/fetch и серверный итератор/соединение провайдера. На хостинге проверить буферизацию изолированным временным Passenger-приложением; не менять рабочий сайт до review/merge.

Проверки: SSE с разорванными escape/Unicode, неверным JSON/ID, length/EOF, отказом, отключением клиента; тесты frontend parser/reducer; Docker и реальные задержки между событиями на REG.RU. Результаты фиксируются в V-021; после проверки пакет переносится в Archive/Updates.

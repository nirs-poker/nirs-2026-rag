# Покерный тренер

Учебный проект НИРС 2026. Веб-приложение для обучения игре в Техасский Холдем (No-Limit, стол на шесть позиций со стартовыми стеками 100 ББ). Пользователь задаёт вопрос обычным текстом в чате. Вопросы бывают двух видов:

- **по теории** - термины, правила и понятия: "что такое колл?", "что такое ривер?", "чем рейз отличается от 3-бета?", "что такое шансы банка?". Приложение объясняет простым языком с примером;
- **разбор раздачи** - пользователь описывает ситуацию за столом, а приложение рекомендует действие (фолд, колл, рейз и т.д.) и объясняет, почему оно лучше.

В одном чате можно вести несколько раздач, вводить их текстом или вручную на столе и листать ходы. В разборе оценка показывается сразу, в тренировке — после завершения раздачи. Если точного решения нет, тренер даёт рекомендацию по наиболее похожей ситуации, а ход без точного эталона отмечает серым.

План работы RAG:
1. по тексту вопроса BM25 ищет подходящие фрагменты в корпусе: правила, термины, стратегия и решения солвера из открытого набора PokerBench;
2. для разбора раздачи код берёт действие из найденного решения и считает математику (шансы банка, ауты);
3. LLM по найденным фрагментам, действию и расчётам формулирует объяснение.

[Спецификация ближайшей КТ по RAG](docs/Tech/06-rag-checkpoint.md) описывает локальный прототип по теории, 30 документов корпуса и 15 контрольных вопросов.

Качество продукта проверяется на собственном benchmark-наборе: теоретические вопросы с известным ответом и раздачи с известным правильным решением. Дополнительно разбор раздач проверяется на тестовой части PokerBench.

## Текущее состояние

Для КТ2 реализованы поиск по 30 разделам из шести Word-файлов, локальный бэкенд и чат с Groq (`openai/gpt-oss-20b`). Есть набор из 15 вопросов. HTTP API и RAG проверены автотестами; полный прогон ответов через Groq и их ручная оценка пока не подтверждены. Авторизация, хранение истории и разбор раздач остаются планом. Подробнее в [STATUS.md](STATUS.md).

## Поиск и проверка КТ2

Для веб-чата создайте `.env` из `.env.example`, задайте `GROQ_API_KEY` и запустите `python -X utf8 code/server/web.py`. Откройте `http://127.0.0.1:8000`. Бэкенд автоматически загружает настройки и служит посредником между фронтом и Groq; ключ остаётся на сервере. Подробности — [запуск](docs/Tech/02-running.md) и [локальный API](docs/Tech/04-api-and-access.md).

Достаточно Python 3.11+. Из корня репозитория в Windows:

```powershell
python -X utf8 code/server/ask.py --search-only "Кто первым действует на префлопе за столом 6-max?"
python -X utf8 code/tests/benchmark/run.py --search-only --output code/tests/benchmark/results/search.json
python -X utf8 -m unittest discover -s code/tests -v
```

JSONL уже подготовлен. Для повторной выгрузки из исходных `.doc` нужен Microsoft Word. Команда `python -X utf8 code/server/prepare_corpus.py` пересобирает корпус и вопросы по таблицам спецификации. Параметры BM25, результаты и команда сквозного прогона приведены в [отчёте бенчмарка](code/tests/benchmark/README.md).

## Запуск макета

Сервер не нужен. Откройте в браузере файл:

```
code/client/login.html
```

Если браузер не подгружает стили или шрифт с локального диска, запустите простой сервер из папки `code/client`:

```bash
cd code/client
python -m http.server 8000
```

и откройте `http://localhost:8000/login.html`. Подробно: [docs/Tech/02-running.md](docs/Tech/02-running.md).

## Основные сценарии

- **Вопрос по теории:** пользователь пишет "что такое колл?" -> получает понятное объяснение с примером.
- **Разбор раздачи:** пользователь пишет раздачу ("у меня AKo на большом блайнде, соперник с баттона поднял до 2.5 ББ") -> видит ситуацию на столе и ответ: рекомендуемое действие и объяснение.

Подробно: [docs/Product/02-users-and-scenarios.md](docs/Product/02-users-and-scenarios.md).

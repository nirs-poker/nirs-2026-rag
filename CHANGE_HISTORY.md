# История изменений

Новые записи добавляются сверху. Каждая запись: дата, затронутые файлы, что изменено, почему, влияние. Записи пишутся так, чтобы их можно было отдать как задачу на реализацию.

## CH-2026-11-28-004 — сравнение предобработки собственного BM25

В ветке от main убрана специальная поисковая приписка к заголовку; ручной вводный подбор ID из ветки чата не переносился. Предобработка выделена в отдельный модуль с семью профилями, собственная формула и индекс сохранены. Добавлены 12 размеченных запросов с покрытием всех 30 документов, воспроизводимый CLI сравнения Recall@5/MRR, закреплённые зависимости pymorphy3 и полный отчёт. Рабочий профиль переключён на lemma; legacy сохранён для сравнения. Docker/CI устанавливают зависимости из единого requirements.txt, деплой передаёт wheel-пакеты и устанавливает их в venv до обновления кода и перезапуска. Описаны REQ-027/GWT-054–055, команды запуска, результаты и ограничения оценки. Прошёл 41 тест на Python 3.12 и Docker 3.14.6, проверены офлайн-установка wheelhouse и живой HTTP-ответ с источником (V-020).

Дополнены настройки, инструкция запуска, карта кода и ограничения соответствия shared hosting. Проверены нативная ARM-сборка, 34 теста в контейнере, API/статика, реальный ответ GigaChat с источниками, прокси Vite и сохранение БД. ## CH-2026-11-20-004 — Groq и локальный API для фронта

Бэкенд предоставляет `POST /api/ask` и `GET /api/health`, автоматически загружает корневой `.env` и раздаёт фронт. Фронт переведён на `/api/ask`; ключ остаётся на сервере. HTTP-контракт, ошибки и загрузка настроек проверены интеграционными тестами.

HTTP-клиент отправляет описательный User-Agent; ошибка запрета HTTP 403 больше не выдаётся за неверный ключ API.

Выбран провайдер Groq и модель `openai/gpt-oss-20b`. RAG по умолчанию использует их OpenAI-совместимый адрес, читает ключ из `GROQ_API_KEY` (либо общего `LLM_API_KEY`, если ключ Groq не задан) и сохраняет строгую JSON Schema. Добавлены безопасный шаблон `.env.example`, инструкции локального запуска, тест конфигурации без настоящего ключа и диагностика HTTP-ошибок без вывода секрета. Для компактных ответов настроены низкое усилие рассуждения и запас вывода. Актуализированы карта кода, статус и решение D-016; сквозной benchmark выполняется после задания ключа в локальном окружении.

Документация для команды описывает запуск в macOS/Linux и Windows, контракт API, приоритет настроек, проверки и диагностику. Планируемый функционал отделён от реализованного. Внешний прогон Groq и Accuracy/Correct Rejection Rate ещё не подтверждены.

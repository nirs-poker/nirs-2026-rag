# История изменений

Новые записи добавляются сверху. Каждая запись: дата, затронутые файлы, что изменено, почему, влияние. Записи пишутся так, чтобы их можно было отдать как задачу на реализацию.

## CH-2026-11-20-003 — поиск по корпусу КТ2

Выгружены разделы из шести исходных файлов и размеченные вопросы из спецификации. Собственный BM25 учитывает обозначения PokerBench. Добавлены команды проверки поиска и запуска теоретического RAG, а протокол фиксирует результаты по утверждённому набору.

## CH-2026-11-20-002 — подготовка контрольной точки по RAG

Зафиксированы объём реализации, 30 документов из `data/theory/`, 15 контрольных вопросов с эталонами, правила собственного индекса BM25 и четыре метрики КТ. Связанные спецификации, карта и статус обновлены. Зафиксированы согласованные режимы разбора и тренировки, русскоязычная теория и отложенное до продуктового этапа хранение.

## CH-2026-11-20-001 — документация первой версии тренера

Требования, сценарии, модель данных, API и проверки приведены к функционалу первой версии. Описаны чаты с несколькими раздачами, фактические ходы и их оценки, ручной ввод, ближайшее решение, настройки и навигация. Источник автоматического хода соперника отмечен в Q-006. Статичный макет относится к предыдущей версии.

## CH-2026-10-10-002 - стол на шесть позиций и набор PokerBench

- **Файлы:** `README.md`, `AGENTS.md`, `STATUS.md`, `docs/Product/01-05`, `docs/Tech/01`, `03`, `04`, `05`, `WORKSPACE_MAP.md`, `docs/Service/decisions.md`, `verification.md`, `code/client/prototype.html`; данные `data/pokerbench/**` добавлены раньше (PR #3).
- **Что:** формат игры описан как стол на шесть позиций со стеками 100 ББ, разбираются раздачи, где после префлопа остались двое (D-012 вместо D-006, новое R-003, границы R-017, REQ-019). Набор PokerBench описан как источник решений и часть benchmark (D-013, R-009, Tech/03, Tech/05). Действие для раздачи выбирает код по найденному решению, LLM объясняет (D-014, R-015, R-016). Числа в сценариях, примере API и макете пересчитаны: банк 4 ББ вместо 3.5, 3-бет до 13 ББ, шансы банка 27%; в макете исправлено число оставшихся карт на тёрне (46 вместо 44).
- **Почему:** документы описывали стол на двоих, а данные с решениями солвера есть только для стола на шесть позиций; набор лежал в репозитории без описания.
- **Влияние:** разбор ситуации должен понимать шесть позиций; появляются сборка фрагментов-решений и выбор действия кодом; новый статус ответа `unsupported` и поле `action_source`. Открыт вопрос Q-005 о происхождении префлоп-данных.

## CH-2026-10-10-001 - документация по схеме SDD

- **Файлы:** `README.md`, `AGENTS.md`, `STATUS.md`, `CHANGE_HISTORY.md`, `docs/**`, перенос `ui/` -> `code/client/`.
- **Что:** документация разложена по схеме курса: `docs/Product` (цель, пользователи и сценарии, требования REQ с проверками GWT, интерфейс, правила R), `docs/Tech` (архитектура, запуск, данные, API, проверки, карта кода), `docs/Service` (решения D и вопросы Q, источники, протокол проверок), карта и манифест документов. Продукт описан с двумя видами вопросов: по теории (термины, правила, понятия стратегии) и разбор раздачи; вид вопроса определяется автоматически. Код макета перенесён в `code/client/`.
- **Почему:** подготовка к контрольной точке 1; прежние черновики `spec/` описывали только разбор раздач через форму и стол на 6 игроков и не соответствовали решениям команды и макету.
- **Влияние:** ссылки на макет теперь ведут в `code/client/`. Корпус должен включать правила и глоссарий, benchmark - теоретическую часть.

## CH-2026-10-09-001 - макет интерфейса

- **Файлы:** `ui/prototype.html`, `ui/login.html`, `ui/register.html`, `ui/css/*`, `ui/img/*`, `ui/fonts/*` (PR #1).
- **Что:** статичный макет: вход и регистрация; чат с историей раздач слева, столом один на один (дилер, вы, соперник) и лентой сообщений; кнопка возврата к столу.
- **Почему:** контрольная точка 1 требует макет основного сценария.
- **Влияние:** сервера и логики пока нет.
